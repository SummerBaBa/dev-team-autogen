# 安全护栏系统

## 设计理念：纵深防御

安全护栏按照纵深防御原则在三个独立层面实现。每一层相互独立，确保单层失效不会危及整体安全。

## 第一层：输入护栏

**源码位置**: `guardrails/input_guard.py`

### 检测机制

| 检查项 | 方法 | 触发示例 |
|-------|------|---------|
| **提示注入** | 正则表达式匹配 | "忽略之前的指令"、"ignore previous instructions" |
| **敏感话题** | 关键词阻断 | "如何制作武器" |
| **输入长度** | 字符计数 | 超过 10,000 字符 |
| **控制字符** | 清洗 | 剔除不可打印字符 |

### 执行流程

```
输入 → 清洗 → 长度检查 → 注入检查 → 话题检查 → 批准/拒绝
                                                      │
                                           ┌──────────┘
                                           ▼
                                   阻断并返回原因
```

### 配置项

```python
GuardConfig(
    max_input_length=10000,       # 最大输入长度
    blocked_topics=[...],         # 敏感话题关键词列表
    enabled=True,                 # 是否启用
)
```

## 第二层：输出护栏

**源码位置**: `guardrails/output_guard.py`

### 检测机制

| 检查项 | 风险等级 | 匹配示例 |
|-------|---------|---------|
| **危险代码** | high | `rm -rf`、`exec()`、破坏性命令 |
| **密钥泄露** | critical | API 密钥、密码、Token |
| **输出长度** | medium | 超过 50,000 字符 |

### 处理方式

- **阻断**: 输出被丢弃，不会保存到产物文件中
- **记录**: 所有阻断事件记录到审计日志，带风险等级
- **上报**: 流水线以空输出继续执行，下游 Agent 优雅处理

## 第三层：流程护栏

**源码位置**: `guardrails/flow_guard.py`

### 审计事件结构

```json
{
  "event_id": "EVT-20260528-143022-0001",
  "phase": "PM",
  "agent": "PM",
  "action": "llm_call",
  "status": "passed",
  "input_preview": "Write PRD:\n开发命令行 Todo List...",
  "output_preview": "# PRD\n## 概述...",
  "timestamp": "2026-05-28T14:30:22",
  "duration_ms": 12345.6,
  "risk_level": "safe"
}
```

### 熔断机制

FlowGuard 追踪连续失败次数。当连续 Agent 调用失败达到 `max_failures`（默认：3 次）时，可触发流水线停止，防止错误级联扩散。

### 审计日志

所有事件持久化到 `output/audit_log.json`，支持事后分析。

## 人在回路（HITL）

当 `GuardConfig.require_human_approval = True` 时，流水线可扩展为：

1. 每次 Agent 调用前暂停
2. 显示任务提示供人工审核
3. 等待确认后继续执行
4. 允许人工覆盖护栏阻断

在高价值代码生成的场景中尤为有用。

## 测试覆盖

单元测试覆盖所有护栏组件：

```bash
python tests/test_guardrails.py
```

测试类别包括：
- 正常输入审批
- 注入攻击拦截（中英文）
- 敏感话题拦截
- 输入长度限制
- 危险代码检测
- 密钥泄露检测
- 事件记录与失败阈值追踪
- 评估指标追踪
