# 架构设计

## 概述

本项目使用 Microsoft AutoGen 0.7 构建多Agent软件开发流水线。三个专业化的AI Agent通过顺序协作，将产品需求转化为经过测试的生产级代码。

## 设计原则

1. **关注点分离**: 每个Agent拥有单一且明确的职责
2. **纵深防御**: 在输入、输出、流程三个层面设置多层安全护栏
3. **可观测性**: 每一步操作都被记录、追踪和量化
4. **框架无关核心**: Agent 定义通过工厂模式抽象，可轻松切换底层框架

### Agent 角色

| Agent | 模型 | 温度 | 职责 |
|-------|------|------|------|
| **PM** | Qwen3-8B | 0.3 | 分析需求，撰写结构化 PRD |
| **Developer** | DeepSeek-V4-Flash | 0.2 | 根据 PRD 实现代码 |
| **QA** | Qwen3-8B | 0.3 | 测试代码，生成问题报告 |
| **Fixer** (Dev) | DeepSeek-V4-Flash | 0.2 | 修复 QA 发现的问题 |

### 执行模型

- **顺序执行**: Agent 依次运行，每个 Agent 接收前一个的输出
- **异步**: 基于 Python `asyncio` 实现非阻塞执行
- **超时保护**: 每个 Agent 调用可配置超时时间，防止卡死

## 护栏集成

安全护栏包裹每一次 Agent 交互：

1. **调用前**: InputGuard 在流水线启动前验证需求
2. **调用后**: OutputGuard 在每个 Agent 响应持久化前进行校验
3. **全流程**: FlowGuard 记录每个事件用于审计

## 配置管理

所有配置集中在 `config.py` 中，使用 dataclass：

```
AppConfig
├── ModelConfig    → LLM 端点、模型、温度
├── GuardConfig    → 护栏阈值、关键词列表
└── EvalConfig     → 追踪、Benchmark 设置
```

配置可通过环境变量覆盖，适用于不同部署环境。

## 输出产物

每次运行产生五个结构化产物：

1. `01_PRD.md` — 产品需求文档
2. `02_CODE.md` — 初始代码实现
3. `03_TEST_REPORT.md` — 测试结果和问题列表
4. `04_FIXED_CODE.md` — 问题修复后的代码
5. `05_REGRESSION_REPORT.md` — 回归验证报告
